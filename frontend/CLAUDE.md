## Project state

This is a `create-next-app` scaffold (Next.js 16.3.4, React 19.2.8, Tailwind CSS 4) with Material UI 9 wired in as the component library. App code so far: the layout/navigation shell, i18n, placeholder board pages, and the sign-in/sign-up pages wired to the Better Auth client (see Architecture notes).

**Read `SPEC.md` before implementing any feature.** It is the target-architecture spec for the app to be built here (a real-time collaborative board/project tool, Trello-like) and defines requirements that aren't derivable from the scaffold. Key constraints worth internalizing up front:

- The backend keeps board state in Postgres and publishes changes to Kafka (transactional outbox); the frontend reaches both only through the backend's HTTP/real-time APIs — never connect directly to Kafka or Postgres from the frontend.
- Optimistic UI is allowed only as a temporary rendering technique; board state must always reconcile back to the backend-authoritative event flow (see SPEC.md §3 for the mutation lifecycle).
- Auth is handled by Better Auth on the backend boundary — the frontend integrates with it (registration/login/logout/OAuth/session/protected routes) but must not implement password hashing or auth logic itself.
- SPEC.md §6 recommends a `src/{app,components,features,lib/{api,auth},hooks,types}` layout with a dedicated API client layer instead of scattering `fetch` calls through components — adapt as needed once real structure emerges.
- `any` is disallowed without a documented reason; all API responses, domain objects, board events, and auth state must be typed.

## Commands

Package manager is bun (`bun.lock`, `packageManager: bun@1.4.2` in `package.json`).

- `bun install` — install dependencies (postinstall scripts are blocked except for `sharp` and `unrs-resolver`, per `trustedDependencies`/`ignoreScripts` in `package.json`)
- `bun dev` — start the dev server (http://localhost:3000)
- `bun run build` — production build
- `bun run start` — serve the production build
- `bun run lint` — run ESLint (flat config, `eslint-config-next`)

No test runner is configured in this project.

## Architecture notes

- App Router under `app/`. TypeScript strict mode, path alias `@/*` → project root (`tsconfig.json`).
- Styling is Tailwind CSS 4 via `@tailwindcss/postcss` (`postcss.config.mjs`), global styles in `app/globals.css`.
- UI components come from Material UI (`@mui/material`, Emotion, `@mui/icons-material`); Tailwind is kept for layout/utilities. The MUI theme options live in `theme.ts` (CSS variables, green light/dark palettes switched via a `.dark`/`.light` class on `<html>`, font = Geist, self-hosted via the `geist` package (`geist/font/sans`/`mono`, `next/font/local`) — not `next/font/google`, because the k8s pod can't reach Google Fonts); `components/providers/AppThemeProvider.tsx` builds the theme with the MUI locale pack (`ukUA`/`enUS`) matching the current locale.
- `app/layout.tsx` wraps the app in `NextIntlClientProvider` → `AppRouterCacheProvider` (`@mui/material-nextjs/v16-appRouter`, `enableCssLayer: true`) → `AppThemeProvider` → `CssBaseline` + `AppHeader` + `<main>`, plus `InitColorSchemeScript attribute="class"` to avoid a dark-mode flash.
- i18n: `next-intl` without i18n routing (no locale prefix in URLs). App locales are `ua` (default) and `en` (`i18n/config.ts`); the active one comes from the `locale` cookie, falling back to `Accept-Language`, then `ua` (`i18n/request.ts`), and is changed via the `setLocale` server action (`i18n/actions.ts`). `ua` is the app-level id (cookie, `messages/ua.json`, switcher), but next-intl/`<html lang>` receive the BCP 47 tag `uk` (`LOCALE_TAGS`) — so `useLocale()` returns `uk`/`en`; convert with `toAppLocale`/`toLocaleTag`. All UI text must come from `messages/{ua,en}.json` via `useTranslations`/`getTranslations`; keys are type-checked against `messages/ua.json` (`global.d.ts`). Reading the cookie makes every route dynamic.
- Layout components in `components/layout/`: `AppHeader` (sticky AppBar, desktop nav + mobile Drawer, active item by `usePathname`; takes `user` from `getSession()` in `app/(main)/layout.tsx` and shows `UserMenu` — avatar + menu with name/email and sign-out (`authClient.signOut()` + `router.refresh()`) — instead of the sign-in/sign-up buttons and Drawer items when signed in), `LocaleSwitcher`, `ColorSchemeToggle` (circular `Skeleton` until mounted — `useColorScheme().mode` is `undefined` on the server), `PageContainer` (`Container maxWidth="lg"` + vertical padding + optional `h1` title and `actions` rendered to its right, wrapping below on narrow screens — use for regular pages; the board page is full-width instead), `nav.ts` (nav items). `components/ui/LinkButton.tsx` is a client wrapper for `Button component={NextLink}` so Server Components can render link buttons.
- Shared form code: `components/form/` — `FormTextField` (MUI `TextField` bound to RHF via `useController`, translates the schema error key into `helperText`; `type="password"` renders `PasswordField` with a visibility toggle); `lib/validation.ts` — `ValidationKey`/`isValidationKey` (keys under the `Form.validation` messages) and common Zod pieces (`requiredString`). Feature schemas (`lib/auth/schemas.ts`, `lib/boards/schemas.ts`) build on them.
- Auth (Better Auth client only — the server lives in the backend `auth` service): `lib/auth/client.ts` exports `authClient` (`createAuthClient` from `better-auth/react`); `lib/auth/redirect.ts` holds `AFTER_AUTH_REDIRECT` (`/boards`), `signInUrl()` and `safeCallbackPath()` (only same-origin paths from `?callbackURL=`, to avoid open redirects), and the forms + Google button redirect via the `useAfterAuthRedirect()` hook. With no `baseURL` it calls same-origin `/api/auth`, which the k8s ingress routes to the `auth` service; set `NEXT_PUBLIC_AUTH_URL` (e.g. in `.env.local`) to point at the auth service when running without the ingress. `lib/auth/errors.ts` maps Better Auth error codes to `AuthForm.errors.*` messages (`null` = request threw, i.e. network error). Forms use React Hook Form + Zod: schemas live in `lib/auth/schemas.ts` and their error messages are `Form.validation.*` **keys**, not text (keeps schemas locale-agnostic). `components/auth/`: `AuthCard` (card shell + "or" divider + `GoogleSignInButton` + switch link), `SignInForm`/`SignUpForm` (`zodResolver`, `mode: "onTouched"`, server errors via `setError("root.serverError")` shown in an `Alert`, redirect to `/boards` on success). The only OAuth provider is Google (`signIn.social`, absolute `callbackURL`). Protected routes (`/boards/**`) use two layers: `proxy.ts` (Next 16's renamed middleware) does an optimistic `getSessionCookie` check and redirects to `/auth/sign-in?callbackURL=…`; each protected page then calls `requireSession(path)` from `lib/auth/session.ts`, which validates the session via `GET /api/auth/get-session` against `AUTH_INTERNAL_URL` (default `http://auth`, the in-cluster Service — the browser origin is unreachable from the pod; set it in `.env.local` for local dev) and is `cache`d per request. Don't make `/auth/*` redirect signed-in users based on the cookie alone — a stale cookie would loop with `requireSession`. Sign-out lives in `components/layout/UserMenu.tsx`; its `Avatar` uses `referrerPolicy="no-referrer"` (Google avatars reject a foreign `Referer`) and falls back to initials.
- Board pages load data on the server: `lib/boards/server.ts` (`fetchBoards`, `fetchBoard` — `cache`d, `null` on 404/400) calls the `boards` Service at `BOARDS_INTERNAL_URL` (default `http://boards`; set in `k8s/frontend-deployment.yaml`, override in `.env.local` without k8s) with a JWT from `getServerAccessToken()` (`lib/auth/session.ts`: `GET ${AUTH_INTERNAL_URL}/api/auth/token` with the request's cookie). Response types live in `lib/boards/types.ts`. `/boards` lists the user's boards (`BoardListItem`, client component because of `component={NextLink}`); `/boards/[boardId]` calls `notFound()` for missing/foreign boards, shows `BoardInfo` (outlined box with labelled name / role / description, members button in its corner; the skeleton in `loading.tsx` mirrors it) and renders `<BoardView key={board.version}>` (client): `SortableColumn`s of `COLUMN_WIDTH` (`components/boards/constants.ts`, shared with the skeleton) with `SortableCard`s. For OWNER/EDITOR (`canEditContent`): "add card"/"add column" buttons, a "⋮" `ItemMenu` (edit → `ColumnDialog`/`CardDialog` in edit mode, delete → `components/ui/ConfirmDialog.tsx`) and drag-and-drop with `@dnd-kit/react` (columns by the header handle, cards anywhere on the card, across columns; `onDragOver` moves cards live with `move()` from `@dnd-kit/helpers`, `onDragEnd` reorders columns and saves the drop by sending the neighbour id to `moveColumn`/`moveCard`; cancel or a failed save restores the pre-drag layout and shows a Snackbar). Every successful write calls `router.refresh()`; the new `board.version` remounts `BoardView`, so the optimistic local order resets to the server's. Dialogs are keyed by an open counter so each opening starts from the target's values. The header's `BoardMembersButton` opens `BoardMembersDialog` (mounted per opening, loads `listMembers`): the OWNER adds members by email + role, changes roles (`Select`) and removes members; others see the list and can leave (→ `/boards`). Avatars use `initials()` from `lib/users/initials.ts` (shared with `UserMenu`). Form dialogs share `components/form/FormDialog.tsx`; boards API errors map to `BoardsApiErrors.*` messages via `boardsApiErrorKey()` (`lib/boards/errors.ts`).
- Boards: `components/boards/CreateBoardButton` (in the `/boards` header via `PageContainer actions`) opens `CreateBoardDialog` — RHF + Zod form (`lib/boards/schemas.ts`, reuses `requiredString` and `FormTextField`; input `maxLength`s mirror the boards DB columns). On success it navigates to `/boards/<id>` (button stays loading meanwhile); failures map to `BoardsApiErrors.*` in an `Alert`. `lib/boards/api.ts` (`createBoard`, `createColumn`, `createCard`) calls same-origin `POST /api/boards…` (k8s ingress → boards service) with `Authorization: Bearer <jwt>` — backend services other than auth don't read the session cookie. The token comes from `getAccessToken()` in `lib/auth/token.ts` (`authClient.token()` via the `jwtClient()` plugin; browser-only, in-memory cache refreshed 60 s before `exp`, concurrent callers share one request; `clearAccessToken()` on sign-out in `UserMenu` and before the single retry on a 401). It expects `201` with the board; errors are `BoardsApiError` with a typed `code` (`unauthorized|forbidden|notFound|userNotFound|alreadyMember|validation|network|generic`; 422 → `userNotFound`, 409 → `alreadyMember`). There is no `NEXT_PUBLIC_*` override — this only works behind the ingress (`skaffold dev`, `http://localhost`).
- Loading UI: `(main)/loading.tsx` and `auth/loading.tsx` render the generic spinner `components/ui/PageLoader.tsx`; `boards/loading.tsx` and `boards/[boardId]/loading.tsx` are MUI `Skeleton`s mirroring their page's layout — keep them in sync when those pages change. Loading labels come from the `Common.loading` message.
- `app/globals.css` declares `@layer theme, base, mui, components, utilities;` before `@import "tailwindcss"`, so Tailwind utilities override MUI styles (e.g. `<Button className="mt-4">`). Tailwind's `dark:` variant follows MUI's `.dark` class, and MUI palette CSS variables are exposed as Tailwind colors (`bg-primary`, `text-text-secondary`, `bg-paper`, `border-divider`, ...). Prefer MUI props/`sx` for component styling and Tailwind for layout.
- `app/layout.tsx` types its props via generated route types (e.g. `LayoutProps<"/">`) instead of a hand-written `{ children: React.ReactNode }` interface — part of Next 16's typed-routes generation. Confirm current conventions in `node_modules/next/dist/docs/` (see AGENTS.md above) before assuming older Next.js prop-typing patterns.
- `next.config.ts`: `output: "standalone"`, wrapped with `createNextIntlPlugin()`.
